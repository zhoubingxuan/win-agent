Endpoints — local server or cloud API

One click switches the whole agent between a local model server and a cloud API. Every endpoint keeps its own URL, key and model.

New endpoint kind
local API

Max steps: 0 means no step limit - a long task may take as many rounds as it needs. What still stops a turn is repeated work: the same call returning the same answer twice is refused on the third try, and the Stop button is always there.

Sandbox (on by default): every file path has to point inside the working directory, and a PowerShell script is read before it runs - a path that leaves the folder, a $env: that resolves outside it, or a disk-destroying command is refused instead of approved. Turn it off to work outside the folder.

On by default. When the model asks for exactly the same call and gets exactly the same answer twice, the third one is answered with a note instead of being run again - the commonest way a small model burns a turn. A poll whose answer keeps changing is never stopped, and switching this off returns to plain step-by-step execution.

On by default. When a task has several parts the model writes them into a checklist (the todo tool) and the chat shows it live. If it then tries to answer while an item is still open, it is told which ones - at most twice - before the turn may end. The list is saved with the conversation; switching this off only removes the reminder.

Agent mode — how closely the model is supervised

Auto is the default: a local model below 14B gets the guided procedure, while a cloud endpoint or a local 14B+ model gets the expert fast path. Guided adds a numbered procedure, spells out every argument, allows one tool per step and withholds the raw shell. Normal is the plain prompt. Expert keeps the prompt short, does not nag about a checklist and lets the model batch independent tool calls.

Model profile — measured capability

Auto mode can stop guessing from the model name. One short run of seven file tasks measures whether this endpoint can call tools, patch code, recover from a missing file and follow an instruction. The result is stored per endpoint + model and is used only while the mode is Auto.

Output detail — how much of the process the chat shows

A view setting, nothing else: the agent does exactly the same work, and the whole record is written to the data folder either way. Answer only shows your message and the model's reply; + thinking adds the model's reasoning in a block you can fold; + tools & usage is the machine room — every tool call with its arguments and result, step markers and token counts.

Context window and robustness

Small local models have a small window. The agent measures every request and quietly drops the oldest exchanges (and squeezes huge tool results) when it would not fit — the stored conversation is never shortened. Leave 0 to use the length the endpoint reports.

              Ask every local server — LM Studio (port 1234) and Ollama (port 11434) — which models it
              can load, and show them all in one list. Picking a model from another server switches
              the endpoint for you. Everything stays on this machine.
            

            

              
            

            


            
MCP — Model Context Protocol

            

              MCP lets the agent use tools that live in other programs: a filesystem server, git,
              a database, your own HTTP service. Add one with its start command (stdio,
              e.g. npx -y @modelcontextprotocol/server-filesystem D:\) or with a URL
              (http). Their tools appear in the model's tool list as
              mcp__<server>__<tool> and ask for approval before they run.
            

            

              
              
              
            

            

              The other direction: win-agent can also be the server — another agent starts
              it with --mcp-server and uses these Windows tools. Nobody can press Approve
              there, so destructive actions are refused unless the switch above is on.

              Turn a tool off with its switch to hide it from the model. All on = all enabled.
            

            

            


            
Change log and undo

            

              Every change the tools make is appended to the audit log, and each one that can be
              restored faithfully can be rolled back from this list - today, tomorrow, or next
              week. Files are copied aside before they are touched; the copies are kept for the
              number of days below, so a restart loses nothing.

Skills

            

              A skill is a procedure the model loads only when a task matches it - steps, examples,
              things that went wrong last time. The prompt carries one line per skill; the body is
              fetched when it is needed, so ten procedures do not fill a small context window.
              Each skill is a folder under data/skills/, so a file you write there by
              hand shows up in this list too.
